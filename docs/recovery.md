# 恢复与排障

更新：2026-10-09。

SSH断联先确认实际IP、网络与供电，再连接 `ssh pi@192.168.137.3`。IP可能变化，核对目标身份。历史失联无充分证据归因过热或掉电，不能只看指示灯判断。

UART异常时先退出其他占用程序，再运行 `python3 operator_cli.py doctor`。这不解锁或切模式。心跳证明接收，参数/命令回复证明双向通信；仅串口打开或有姿态数据不等于可靠。

历史CRC/帧错误根因未确定，近期正常不等于修复，不靠无限重试或关闭检查掩盖问题。COM25与当前UART7无关，不按早期接线记录操作。

模式命令超时可能已执行，先读心跳。未确认上锁时停止扩大测试并现场检查，需要时切断动力电源。软件上锁和开发板关机都不等于电调电池断电。

config/backups保留早期启动配置与验证DTB；恢复前必须比较差异，不直接覆盖后续配置。UART7正常时无需回滚或重跑enable_uart7.py。

曾发现VS Code Server安装不完整；它不是相机或飞控通信故障的同义词。修复应核对版本与文件，不先删除整个用户目录。历史日志清理前备份路径见根README。

默认启动无日志。诊断应有时长上限，结束释放设备。正常关机在确认测试结束后执行，不能作为飞控停机手段。
