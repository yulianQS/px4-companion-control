# Web v0.6 双摇杆控制

更新：2026-10-10。入口仍为 `python3 web_control.py`，网页运动页 `http://192.168.137.3:8081/#motion`。使用已有venv，不增加依赖、参数写入、自动启动或运行日志。

## 操纵含义

用户选择沿用Offboard速度控制。左杆上下控制上升/下降速度，左右控制逆/顺时针偏航角速度；右杆上/下控制机头前/后速度，左右控制左右侧移。右杆俯仰/横滚是操纵轴名称，不是直接设置姿态角；左竖杆是升降控制，不直接设置电机推力。所有轴均自动回中，中立目标是零速度，不是关电机。

默认最大水平速度0.20m/s、垂直速度0.20m/s、偏航30度/s，8%圆形死区；两轴对角输入按向量限幅，不使平移总速度超过上限。开发板根据实时机头朝向转换成局部NED速度，上升vz为负。非零速度变化限制加速度0.3m/s²、角加速度60度/s²；独立松杆对应轴立即回零。实际机体减速存在动力学过程，不保证瞬间停在原处。

## 与其他控件协调

1. 保留全局“启用实机控制”开关、未解锁模式切换和普通解锁逻辑。
2. 进入OFFBOARD后即可启用双摇杆，允许未解锁和地面调试；不会因为拖杆自动解锁、切模式或起飞。实际动作需要用户手动解锁；点击解锁会清除地面调试杆量，随后重新启用摇杆操纵。
3. 平移/转向/升降/起飞任务运行时，点击“摇杆接管 / 取消当前任务”会在开发板取消旧目标，不自动恢复。执行LAND时由PX4完成降落，不混入摇杆速度。
4. 摇杆控制期间自动任务与起飞按钮禁用，降落按钮保持可用；后端同样检查，不依赖按钮禁用。
5. 退出摇杆时反馈有效则捕获退出时位置并保持，随后可提交新任务。重复/迟到的旧退出请求不会清除新任务目标。
6. 手动解锁、降落、关闭控制、地面上锁和模式操作先撤销摇杆来源，再执行原有逻辑；输入帧不能覆盖LAND。取消网页额外添加的10秒自动上锁计时，PX4自身配置与检查保持原状。
7. 单个手指松开只回中对应摇杆；另一杆继续工作。页面失焦、隐藏或切到其他页面时回中并尝试结束摇杆会话。不能仅靠浏览器退出事件保证收到请求，开发板另有0.5秒输入超时。

## 分层和数据流

```text
web/joystick.js：双指/鼠标/键盘 → 四轴[-1,1]输入，约10Hz HTTP
  ↓ POST /api/control/stick（沿用控制者、同源检查）
web_flight.py：检查租期、会话、顺序与控制来源，只更新内存
  ↓ 唯一开发板20Hz发送线程
joystick_control.py：死区/限幅/实时机头转换/新鲜度/超时 → NED速度+yaw_rate
  ↓ 复用TelemetryLink.send_motion，frame=1、type_mask=1479
UART7 / TELEM1 → PX4速度、姿态与电机内环
```

`stick_start`/`stick_stop`走既有action接口并去重；连续输入走单独stick接口，不等待MAVLink ACK，也不在HTTP线程发送MAVLink。输入包含服务器生成session、递增sequence、throttle/yaw/pitch/roll。初始第一帧必须中立；拒绝旧会话、重复/乱序、NaN/无限值/布尔值及越界输入。只用服务器单调时钟计算输入年龄，迟到请求不能复活超时会话。

GET /api/status增加joystick状态、板端输入年龄与实际计算目标，control.source标明monitor/zero/task/joystick/hold/px4_land。没有第二个串口连接或新增控制线程。唯一发送线程选择来源并持锁完成写串口，避免切换后漏发前一来源目标。

## 停更与现有限制

0.5秒无新输入、租期过期、心跳失联、偏航反馈陈旧或退出Offboard会停止旧杆量。输入停更首先输出零速度；有效定位下可保持当时位置。原任务不恢复，新摇杆会话需重新启用和中立握手。这里的输入停止机制不等于已完成整机断联/接管保护验证，未修改PX4安全参数。

手动速度摇杆使用当前偏航转换方向，不依赖固定位置原点，位置/ODOMETRY重置不再直接锁止摇杆；不要求已解锁或在空中。启用需要实机控制开关、双向连接、OFFBOARD与就绪设定值流；偏航反馈需新鲜有限。自动位置任务仍需要定位与重置检查。历史航向适用性、测距、估计器重置及UART间歇性坏帧尚未解决，PX4仍会判断能否接受Offboard和解锁，软件接入不代表实际飞行可用性通过。
